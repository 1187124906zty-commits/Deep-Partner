# 科研项目与文件

组织方式服务于当前计算与复现。先读入口、依赖声明、配置、数据来源、运行记录与引用关系，再调整结构。已有项目优先修复职责和路径问题；小程序可以只有几个文件，不为统一目录迁移整个项目。

随规模分离源程序、参数配置、有效检查、作业脚本、数据与结果。README 给出问题与运行入口，环境声明给出需要的依赖；配置包含影响结果的参数、单位与随机性条件。数据和结果明确来源、版本与可写范围，大文件按已建立的远端映射保存。报告图表能追到产生它们的输入、配置和程序。

对 FEM/PDE/DEM/CFD/ML 等计算沿用适用的物理编程与验证技能，针对当前主张选择检查。能运行、lint 通过和目录整齐分别不能替代模型与数值正确性。

## 判断文件是否冗余

输出清单包含路径、实际用途/证据、是否被引用、能否重建和建议处理。下列是调查方向，不能仅按扩展名执行清理：

- 缓存、临时构建产物、下载中间件：核查生成工具、活动进程和恢复用途；已无恢复需要且可重建时可列为清理候选。
- 内容重复文件：普通文本先用内容比较/diff；二进制在需要确认相同时可做哈希或字节比较。内容相同仍可能承担不同路径契约，不因此自动删除。
- 旧实验与相似脚本：检查实际命令、配置、种子、数据版本、运行预算和论文引用。区分废弃尝试、有效对照与必要历史。
- 多种格式与副本：PDF/PPTX、源图/SVG/PNG、原始/处理数据、集群验收副本、输入/输出可能各有用途，不能当作同一文件的无效重复。
- 看似未使用的文件：文本搜索没有引用不能排除动态加载、glob、配置、Notebook、插件、Slurm 作业和外部调用。用途仍不清楚时保留并标明未知。

原始数据、原论文、关键失败记录、基准、锁文件与产物证据应按用途保护。文件名含 old、backup、final2 或时间较早都不足以判断为垃圾。

本分支默认交付调查与建议。用户已经要求清理时，在其授权范围内处理已判定的候选并保留必要的恢复路径；对尚有用途歧义的文件只隔离或保留，明确影响。完成清理后运行受影响入口/测试，并检查科研结果的复现依赖；没有实际运行的部分保留未验证状态。
