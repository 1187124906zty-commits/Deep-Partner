# DeepTutor 扩展功能说明

日常入口是 DeepTutor。用户在同一研究项目中提出问题、补充资料和讨论结果；Tutor 按任务调用检索、Code 与工作台。Dify 的并行取证、成果交付与原生触发流程保留来源状态、版本与处理记录。完整入口和高强度实测见 [工作流与高强度验收说明](工作流与高强度验收说明.md)。

## 三个主要职责

| 模块 | 负责的工作 | 交付或保存的内容 |
| --- | --- | --- |
| DeepTutor | 理解研究问题、约束和资料；提出思路；按需检索和委派；解释证据与下一步 | 当前研究问题、判断依据、需继续讨论的事项 |
| Code Agent | 编程、数据处理、计算、必要测试与偏差诊断；整理技术成果 | 程序、输入来源、结果、实际检查、失败解释、适用范围及交接说明 |
| 研究工作台 | 管理共享项目、资料、成果、批注与版本；供 Tutor 定向读取和检索 | `src/`、`data/`、`results/`、`docs/` 和原生稿件等实际项目内容 |

Code 的计算结果和工作台的保存回执分别报告。保存成功证明成果已写入；科学结论仍取决于实际参照、计算检查和证据范围。

## Dify：研究成果交付

[打开当前工作流](https://tutor.example.invalid/dify/app/5c9d68ae-3847-4774-8e94-ecbfa9543e25/workflow)。画布上方用三张说明卡标明 Tutor、Code、工作台的职责；下方六个可执行节点依次完成：

| 步骤 | 功能 | 不满足条件时 |
| --- | --- | --- |
| 成果交付请求 | 接收当前会话自动提供的交付编号和授权 | 过期授权返回明确错误 |
| 项目与版本校验 | 绑定账户、项目与工作区，读取规范和技能，核对版本 | 停止交付，要求刷新当前项目状态 |
| 成果版本化保存 | 保存指定产物，保留版本，回读内容并登记回执 | 保留实际状态，用同一交付编号继续查询 |
| 成果保存与记录核验 | 核对当前成果与原生处理记录 | 已保存与最终核验状态分别报告 |
| 交付回执生成 | 整理项目、路径、版本、处理记录和证据范围 | 缺少必需字段时不宣告完成 |
| 交付结果 | 向 Tutor 返回实际成果位置 | Tutor 可以继续读取或检索 |

原先画布中分散的账户、规则、参数、回执与历史检查统一到适配层。既有工具名称和调用方式保留，常规交付使用职责明确的核验工具。研究检索与代码执行在原会话中按需进行，无需为一次保存重新运行。

## 按目的选择检索

| 目的 | 接口 | 结果的含义 |
| --- | --- | --- |
| 找官方网页、机构或期刊页面 | `workbench_web_search` | 网页标题、链接和摘要片段，附真实来源与状态 |
| 找论文题录 | `workbench_paper_search` | 作者、标题、年份、标识符与可用摘要；全文阅读另行进行 |
| 在已有项目资料中查证 | `workbench_knowledge_search` | 当前项目关联知识库中的检索证据 |
| 查看配置了哪些来源 | `workbench_search_sources` | 配置状态；是否能取得本次结果由实际检索确定 |
| 阅读原文和定位 | `workbench_reader`、文献附件工具 | 原始材料或定位结果，保留来源身份 |

Tutor 的 `research_workbench` 同时提供 `search` 动作：`search_kind=web` 查询网页，`papers` 查询项目论文题录，`sources` 查看来源配置，`page` 读取一个已知公开网页。检索与读取无需先启动成果保存。

### 已采用的 Dify 现成模块

已安装的 **WebScraper** 用于独立的“网页证据读取”流程：公开链接 → 正文读取 → 来源与正文整理 → 返回证据。关闭模型摘要，保留原链接、读取时间及截断标记。Tutor 根据正文继续判断。该流程不修改项目文件；访问验证或限流时停止并说明原因。

核查过的可选模块及取舍：

| Dify 模块 | 当前取舍 | 原因 |
| --- | --- | --- |
| WebScraper | 已接入并实际读取公开文章 | 当前已安装，适合从检索链接继续取得正文 |
| HTTP、Code、工具节点 | 已用于交付与网页证据流程 | 处理明确接口和结构化结果，无需重复模型推理 |
| Tavily Search / Extract | 可配置的后续检索来源 | 需要自己的 API Key；当前账户未配置 |
| Google Search | 可配置的后续检索来源 | 官方插件使用 SerpApi，需要密钥和配额 |
| Jina Reader | 可替换或补充的网页读取方式 | 官方插件需要配置 Jina 凭据 |
| DuckDuckGo | 暂不重复安装 | 与当前公共检索链路高度重叠；不能假定换插件会消除来源波动 |
| SearXNG | 暂不新增部署 | 需要可用实例；增加一个同样依赖外部搜索源的服务前，应先确定维护收益 |
| 知识检索节点 | 保留给确实由 Dify 管理的知识库 | 当前项目知识库继续由现有工作台与 Tutor 管理，避免无目的复制 |

能力与配置要求核对自 [Dify 官方插件目录](https://marketplace.dify.ai/)、[Tavily](https://marketplace.dify.ai/plugin/langgenius/tavily)、[Google](https://marketplace.dify.ai/plugin/langgenius/google)、[Jina](https://marketplace.dify.ai/plugin/langgenius/jina_tool)、[DuckDuckGo](https://marketplace.dify.ai/plugin/langgenius/duckduckgo)、[SearXNG](https://marketplace.dify.ai/plugin/langgenius/searxng)。是否采用以实际任务、已有凭据和测试结果判断。

明确选择 `scholar_mcp` 时只报告 Google Scholar 的真实结果或失败。`auto` 在首选来源失败时可以尝试 Crossref，返回中标明实际来源及切换原因。Crossref 题录不能冒充 Scholar 检索或论文全文。题录核验超时时保留已取得的原检索结果，并标记未核验项。

## 检索失败后的动作

| 状态 | 系统行为 | 接下来的动作 |
| --- | --- | --- |
| 临时读取断线 | 只对读取请求有限重试一次 | 持续失败时检查网络或服务 |
| 两分钟内重复的公共网页查询 | 复用已成功取得的结果，保留原检索时间并标明缓存 | 减少重复请求；失败结果不缓存 |
| 超时 | 返回 `timeout` 与恢复提示 | 稍后重试或选择其他来源 |
| 限流 | 返回 `rate_limited`，不密集重试 | 等待限流解除或明确切换来源 |
| Scholar 要求人工验证 | 返回 `verification_required` | 在搜索工具的浏览器完成验证后重试 |
| 搜索正常但无匹配 | 返回成功的空结果 | 调整关键词或范围 |
| 上游检索不可用 | MCP 返回工具执行错误及原因 | 不能据此判断“没有相关文献” |
| 写入响应丢失 | 不自动重放写入 | 先查询同一任务，避免重复执行 |

## 工程依据与验收

架构采用 Anthropic 对工作流、工具设计和上下文的工程建议，错误语义参考 MCP 明确版本规范。来源与适用限制见 [工程依据](agent-engineering-evidence.md)。这些文章提供设计依据；当前系统的实际可用性由回归测试、真实检索、真实交付及界面检查判断。

本轮修改围绕现有会话、Code 和工作台展开。原有论文下载、稿件、图表、汇报和知识库工具继续可用；未逐一重新测试其全部操作。Google Scholar 的外部限流、验证与本机搜索桥接在线状态仍会影响可用性，系统保留这些限制并说明恢复动作。
