# 关键句表达工作流改进

2026年11月3日。作者要求修改整套写作工作流，使关键位置在相近意思基础上表达直接、顺畅、有力度。作者明确纠正：这不等于把研究难点、方法作用或贡献拔高，也不只是替换本次点名的三个句子。

## 原流程的问题

原评分把准确性和语法放在优先位置，却没有充分检查关键句是否真正表达了科学判断。语法成立但抽象、绕的句子很容易被标为可选优化；执行器只允许必要项，又把这类建议留在了报告中。写作和审稿提示中的统一新颖性主干，也容易将表达要求误转为贡献重定。

## 当前实现

同一科学意思的表达质量与科学主张强度分别审读。任务理解记录本轮表达要求；现有稿件局部润色保留主线，不自动升级贡献。标杆阶段补充原句及邻句、主语、科学谓语、信息重心与来源，避免把抽象模板当成成品句。

诊断时阅读完整段落，重点查看入口、转折、段尾和摘要收尾。每个选中问题记录原句要说的意思及首次阅读障碍。主句若只宣布存在关系或处理需求，需要据段落中已有信息重组实际动作和对象；这不是短语黑名单，合适的概括和承接仍然保留。

评分维度总分与权重保持原有100分，其中表达20分明确检查信息直接性、句法节奏与学术表达。不能因为句子更短、形容词更强或工具更多而加分。复评对照实际修改，说明读者障碍是否消除、意思是否保留，以及是否通过夸大或削弱原判断制造语气变化。

本轮选择范围包括必要修改及作者明确指定的同义表达改进。后者仍可分类为potential，用selection_basis=author_request和本轮请求的原文引语标明依据；执行器核对引语确实出现在当前请求中，再允许选中。没有被选择的潜在项和全部author_decision不自动执行。该机制用于兑现作者已经提出的修改要求，不将表达偏好伪称为事实错误。

## 代码位置

主要实现位于 research-workbench/server/writing_expression.py、writing_prompts.py、writing_scores.py、writing_revision.py及writing.py。新增测试覆盖作者已指定表达项的选择与应用、未指定项和科学选择的保留、关键句位置上下文，以及原候选不可被复评改写等。相关37项软件测试通过。

服务端和可选写作worker已更新为1111-20261103.6；新增的scientific-expression-review与表达判据已加入MCP技能目录。未发布新UI或激活聊天自动触发扩展。

## 真实回归范围

使用原氯硫五段引言，以及水分稿摘要和未指定的正文段落。回归请求没有列出三个指定替换答案，不采用关键词禁用或人工替换表。实际调用当前原生模型、MCP、表达RAG和适用skill，依次执行诊断、选中项编辑及候选复评。原项目正式稿和上一轮Word不覆盖。

软件测试支持程序行为；真实样本用于检验表达改进，仍需作者阅读判断。两个通用用例及作者点名、摘要收尾两项定向补测均已完成，完整结果保存在 reports/关键句工作流回归/。初次通用回归仍保留了作者不满意的一个入口句，并把摘要验证提醒前移；未据模型高分宣布验收。随后加入作者点名逐项覆盖及摘要提醒的语境判断，定向补测已实际改动三个点名入口句及摘要末句。


## 反馈覆盖与本轮结果

作者点名的原句保留为author_expression_targets。执行器检查这些文字在实际候选中是否改变，并将结果与模型语义复评分开：同一段其他位置改变不算已经回应，literal revised也不等于语言质量通过。该检查随同当前请求保留原话，不依赖三句替换表。

最新服务端和worker已更新，37项相关软件测试通过。点名补测只修改三个指定入口句，其余段内文字保持原样；水分定向补测只改摘要末句，其余摘要文字、数值和条件保持原样。未指定段落回归还改进了机器学习引入句与方法说明，章节安排句保持原样。全部候选仍作为回归产物交作者判断，正式稿和上一轮Word未替换。
