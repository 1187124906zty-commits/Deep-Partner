## 查明的慢速来源与修复

服务端本机测量中，文件和任务接口耗时约 14–28 ms；从本机访问时出现数百毫秒到数秒的额外等待。随后直连还出现连接超时，而使用 Windows 已配置的代理可正常返回。

桌面 HTTP 客户端此前使用 `default-features=false`，没有启用读取系统代理的功能。新版启用系统代理、HTTP/2 和 gzip；实时 WebSocket 也使用同一套代理匹配，通过 HTTP CONNECT 后向原服务建立 TLS。没有修改 Windows 的代理设置。

任务进度由 2.5 秒轮询改为项目持续事件通道，服务端每 350 ms 检查实际变化，只发送变更快照。修正了 Caddy gzip 对事件流的缓冲，事件流以 identity 编码直接传输。网络断开时保留有限轮询后备。

普通 JSON 响应压缩，项目启动的登录状态、用户和项目列表合并为一次请求；带内容版本的静态资源长期缓存。程序文件保留小容量、按修改时间区分的内存缓存，重复打开未改变的文件直接显示，认证变化时清空。

实际测量条件与结果：

| 测量 | 结果 | 条件 |
|---|---:|---|
| 新任务状态写入到页面显示 | 383.8 ms | 隔离软件进度演练，真实存储和事件通道，无模型调用 |
| 启动汇总接口 | 273.9 ms | 本机使用已有系统代理，一次实测 |
| 任务列表接口 | 268.5 ms | 相同条件 |
| 文献列表接口 | 380.5 ms | 相同条件 |
| 小文本文件读取 | 248.1 ms | 相同条件 |
| 程序文件首次打开 | 854.0 ms | 实际界面、源文件未修改 |
| 同一程序再次打开 | 44.1 ms | 全程只产生一次文件读取请求 |
| 任务列表传输 | 41,202 B → 9,280 B | 原响应与压缩响应 |
| 文献列表传输 | 43,811 B → 11,312 B | 原响应与压缩响应 |
| 网站一次冷启动到文献列表 | 4.7 s | 全新浏览器上下文，首次加载静态资源 |

这些结果区分网络、数据量和界面更新延迟，不代表大 PDF 解析、全文翻译或模型计算已经不耗时。网络仍有波动；一次冷启动也曾出现超过二十秒的等待。
