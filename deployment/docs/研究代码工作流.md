# 研究编码工作流指南

代码任务从所属 Deep Partner 项目发起。先用现有项目说明明确研究问题、方法、代码入口和预期输出，再交给 DeepCode 执行。

普通编码使用 `code_engine=agent`，经真实 `deepcode/deepcode-reply` 执行；基于来源的论文复现走原生 `paper2code` 生命周期，保留既有评审交互。交接携带实际项目 ID、发布根、显式选定的输入路径及原始指令。收到的研究指导同时注入普通提示和原生规划、实现提示的构建过程。

沿用现有说明明确问题、方法、入口与预期输出，按有意义的阶段实现，集中执行相关检查，复用仍有效的证据；通过且无新改动、失败或疑点即交付。复用现有求解器与环境，仅按实际需要增加抽象。数值检查须符合具体模型，关注方程、量纲、初边值、稳定性及必要收敛性，以解析解、可信求解器或数据作独立参照。

论文复现保留目标数据与实验，小型诊断运行不能代表复现完成。失败时具体诊断、有限修正；同一路径无新证据就停止，报告真实缺口及影响，替代方案说明范围变化。

基础设施恢复保留原始 ID；一个被中断的原生流程可恢复，通用 `WORKFLOW_INCOMPLETE` 不再自动重试。代码与运行回执保存为项目文件，分别报告代码生成、软件验证、小基准及目标实验状态和未运行工作。软件成功本身不创建知识节点；科学方法或发现可附证据显式记录，既有历史图节点保留。
本次验证：DeepCode 相关测试 17 项、工作台相关测试 7 项通过；真实普通编码链路完成说明文件回交，图谱节点维持 37 个且 ID 集合不变。原有原生规划与实施提示的接入经定向测试验证；本次未重新执行整篇论文复现。

本轮只更新了相关工具桥与 API 工作进程，保留原生 DeepCode 和 Slurm 求解进程及其任务 ID。正在运行或等待交互的旧任务沿用原上下文。科研判断通过模型提示约束；程序直接控制的是自动重试、产物归档与默认入图行为，不能把提示文字当成自动科学验收。
