# 工作台输入输出质量与技能盘点

日期：2026-11-02。默认文本由 Tutor 完成；本轮检查本地能力、补充交付技能初稿，并做有限的结构与读取测试。没有把全部工具逐项宣布验收，也没有将新技能安装到生产账户。

质量需要连接用户要求、来源、专业方法与产物事实。技能约定怎么工作，工具解析实际模板、生成和运行，结果检查再判断是否达标。格式合规、文件已保存、科学结论有依据分别记录。

## 本轮实测发现

`ops/probe_template_style.py` 在内存中新建一个混合字体、两段层级与斜体的测试文本框，调用现有 `pptx_template_tools.py::set_text_preserve_style`。结果见 `reports/template-style-probe.json`：

- 首段西文字体保留。
- 第二段、段落层级、显式中文字体和次段斜体未保留。

这是合成示例的结构测试，没有使用用户模板，也没有运行 Office 渲染。它说明该辅助函数保留的是部分样式，不能单独作为严格模板保真的实现。本轮未修改原共享辅助函数。

新增 `quality-skills/workbench-deliverable-quality`：一个按任务选择分支的主技能，附四份参考说明。内容覆盖论文转幻灯片、模板保真、期刊规范与表达、科研项目与文件整理。没有固化具体期刊字体、统一科研目录或默认清理规则。

技能通过 Codex quick_validate。将包复制到临时目录后，用本地原生 Tutor SkillService 发现并逐字回读了主文和四份参考文件；记录见 `reports/quality-skill-compatibility.json`。这些结果证明包结构与本地读取兼容，尚不证明模型实际使用效果或生产部署完成。

## 输入应该保存什么

按当前任务保存真正影响成果的字段：交付目的、读者/场合、语言与格式、源材料与版本、用户模板、目标期刊/文章类型/投稿阶段、明确约束及允许调整项。可从上下文、附件和项目恢复的信息不用反复询问。示例参数可以暂定，用户指定的硬性模板条件不能无声替换。

正文来源、样式参考和正式要求分别记录。PDF或截图可以支持观察，恢复程度有边界；官方模板、原生格式与明确用户指令才能支撑相应严格条件。需要改变论文主张、承诺兑现和整体漏斗结构时，沿用作者确认要求。

## 各种质量如何落地

模板规则提取成当前任务可用的 profile/manifest：每项有适用对象、要求、来源和允许变化。生成工具使用同一记录，检查工具再读取实际产物比较。PPTX 需要母版/布局/主题、占位符和局部文本覆盖；DOCX 需要样式/默认值/直接格式和多字符范围字体。最终字体与布局也受渲染环境影响，必须看实际导出。

期刊要求来自当前官方指南和模板；发表文章用于观察论证、图证与表达。出版后 PDF 可能经过出版社排版，不等于作者提交规范。没有目标期刊时先保留待调查项。本轮核查了 IEEE 官方模板入口；Nature 页面访问被身份页面重定向阻断，因此没有把其具体规则写入本技能。

程序组织围绕可复现的计算职责。清理文件先说明用途、引用与可再生性，文件名相似、时间较旧、搜索无引用都不能单独证明垃圾。模板源件、原始数据、必要基准、失败证据和运行环境声明按实际用途保留；二进制一致性与普通文本比较采用各自适当方法。

## 接入建议

1. Tutor 保留默认文本与任务理解，将相关技能主文列入原生技能目录，按任务读取必要参考。未部署前本地文件不会自动出现在服务器账户。
2. 当任务需要制作或检查文件时，交给可用的文档/演示工具或本机执行器；输入携带任务身份、原材料和适用要求。
3. 产物与检查结果绑定同一版本。结构检查、最终渲染、程序运行与保存回执分别返回通过/未通过/未验证；阻断的条件只影响其相关主张。
4. 先验收一篇真实论文转用户模板 PPTX，再验收指定期刊的 DOCX/LaTeX，最后验收科学程序的复现与文件整理。每条链都保留能暴露错误的反例，失败后修复再跑受影响部分。
