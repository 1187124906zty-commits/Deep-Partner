# 自动连接、新会话与会话文件侧栏

当前网站和 Windows 程序均已更新到前端构建 25228429，版本 0.4.2。本轮已打开新版桌面窗口，使用原来的用户配置；没有删除研究项目或原始材料。

登录后，程序自动读取账户的模型配置，恢复已配置的所有者电脑工具桥，并检查已配置的 research-cluster-xh5 集群。实际桌面验证中，账户、模型、电脑工具桥和 Slurm 集群均已连通。集群检查使用现有 SSH 配置，不复制密钥或提交计算作业。自动恢复电脑工具桥适用于当前已有的所有者配置；其他账户沿用各自的工具与配对配置。

排查时服务端 HTTP 与登录后的 WebSocket 均能连接，因此没有把截图直接归因为服务器停机。本轮修复了桌面转发时丢失项目参数的问题，以及手动新建会话时重复恢复旧失败草稿的问题。现在启动时仍可恢复未发送内容，点击“新会话”则打开空白会话，保留原恢复记录。

会话中的生成文件链接会直接调用原生右侧文件查看器，受保护的项目文件继续使用账户鉴权。网页来源链接也复用右侧查看器。输入框上方固定的提示行和“查看网页”入口已移除，拖入和粘贴材料仍可用。真实模型回复中的项目说明链接已经点击验证，Markdown 正文在侧栏显示，原会话保持可见。

文献的慢点是原文显示前等待完整语义解析。现在 PDF.js 可以先加载原始 PDF，语义解析在后台继续，解析失败时原文仍可阅读。保留 PDF 的私有 5 分钟缓存和服务器解析缓存，新增阅读器资源的私有 24 小时缓存。本轮同一份 43 页 Feng2014 PDF 在暂停语义准备的验证下，网页首屏约 1.839 秒、实际桌面约 3.646 秒。网络和文献大小会影响耗时。此前另一篇 Feng2015 的解析接口首次准备约 21.477 秒、缓存读取约 0.303 秒，这与首屏显示是不同指标，不能据此计算固定加速倍数。

验收使用当前线上 API 和实际 Windows 程序：网页 9 项、桌面 18 项检查通过；前端 34 项测试、桌面代理 3 项测试通过。实际发送了一条短测试消息，收到回复，验证项目归属、服务端保存、刷新恢复及回复中的文件侧栏预览。测试会话名为“连接验证 · 可删除”。
