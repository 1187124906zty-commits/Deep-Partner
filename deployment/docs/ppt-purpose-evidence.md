# 六种学术 PPT 用途：来源依据与可调整指导

核验日期：2026-11-02。核对对象为 `D:/Development/research-workbench/server/presentation_catalog.py` 的六项 `PROFILES`。本文件提供节点设计与人工评审的参考，未修改该文件，也未部署新的运行约束。机器可读笔记见 `quality-knowledge/ppt-purpose-source-notes.json`。

六种用途保留稳定 ID，作为长期可扩展的用途分类；后续可增加其他用途。当前三种视觉风格是临时、可替换的展示选择，与用途分类分开管理。评分政策 Q1/Q2 尚待用户确认，本文件不设固定合格分。

这里的“来源事实”指指南实际提出的主张，不代表经过对照实验证实的最佳做法。“综合建议”是根据这些主张，为工作台提出的组织和评估方式。学校、学科和会议的局部规定应记录适用范围；不能因此生成全球通用的页数、时长、章节顺序或合格分数。

## 来源共性及适用边界

**来源事实。** MIT BE 将目的、听众、信息选择和证据解释连在一起，明确区分寻求方法反馈与传播研究结果两种情境；还建议准备技术细节用于问答。[S01](https://mitcommlab.mit.edu/be/commkit/slideshow/) AGU 的历史会议指南同样强调组织清楚、取舍必要信息和图形可读，但其文件规范属于 AGU20 的虚拟会议条件。[S02](https://www.agu.org/-/media/files/fall-meeting/preparing-presentation-guidelines.pdf)

**综合建议。** 用途配置应规定“听众结束时能理解或决定什么”以及“哪些信息支持这一结果”，再据实际材料安排页面。内容是否充分需要结合用途判断。可读性、来源追溯和主张与证据匹配适用于六类；章节数、每页图数、正文条目数、固定语气和固定叙事结构不宜由用途规则统一强制。

**节点接入建议。** 先读取用户用途、时长、听众背景、已有材料和机构要求；生成内容计划时为关键主张绑定材料；评审时返回具体缺口及影响。材料缺失时注明“未提供”并调整主张，不能补造结果。下面“必要信息”是有条件的覆盖检查，不要求每项单独占一页。以下用途卡片及评价维度均属综合建议。

## 用途差异一览

| ID / 用途 | 任务目的 | 本次交流应产生的结果 | 优先检查 |
|---|---|---|---|
| group / 组会讨论 | 改进正在进行的研究 | 对诊断、解释或下一步的具体反馈 | 暴露了足够条件，问题可回答 |
| conference / 学术报告 | 向同行讲清研究贡献 | 记住少量可信结论，能开展问答 | 动机、贡献、证据与边界连得起来 |
| project / 项目汇报 | 对照目标说明状态 | 接受交付、调整计划或解决资源依赖 | 目标与实际证据可比较，决策需求明确 |
| proposal / 开题 | 论证值得做且能开展 | 对研究范围、方法和计划形成评议 | 缺口、方案、验证和可行性相互支撑 |
| defense / 学位答辩 | 说明学位研究贡献并接受质询 | 委员会能评价完成工作的质量 | 作者贡献、证据和适用边界清楚 |
| literature / 文献研读 | 理解并评议一项已发表工作 | 对其可信度、局限和可迁移性形成判断 | 原文结论和报告者判断可区分 |

## group：组会讨论

**来源事实。** Newcastle 的组会指南将改进研究作为目的，特别提出展示方法和失败结果；这是校内培训文章的建议，并非要求每次展示所有原始数据。[S03](https://microsites.ncl.ac.uk/fmspgrstudentguidelines/2015/07/30/at-lab-meetings-show-everything/) MIT BE 支持直接说明希望同事提供哪种反馈。[S01](https://mitcommlab.mit.edu/be/commkit/slideshow/#identify-your-purpose)

- **任务目的：** 围绕本次最需要解决的问题展开讨论，可以是研究进展、异常诊断、方案比较或尚未有结果的设计讨论。
- **必要信息：** 当前问题；本次相对已有认识的增量；理解该问题所需的方法条件与数据状态；竞争解释或卡点；已经尝试的处理。
- **证据与反馈：** 让听众能定位证据如何支持或削弱解释。将“请提意见”具体化，例如请比较两个边界条件设置，或判断还缺哪个对照。下一步与反馈问题对应。
- **不适用情形：** 纯文献讨论应采用 literature；练习会议报告可采用 conference 并增加反馈环节。无结果的头脑风暴无需伪造结果页；保密或过量原始材料可按讨论范围提供附件。
- **评价维度：** 问题清晰度；诊断条件是否充分；异常和不确定性是否诚实；反馈问题可回答性；建议能否转成行动。完成结果的数量不作为此用途的通用质量标准。

## conference：学术报告

**来源事实。** MIT BE 建议传播新结果时突出结果及其意义，并根据听众调整技术细节。AGU20 的指导支持清晰组织与简化复杂页面。[S01](https://mitcommlab.mit.edu/be/commkit/slideshow/#identify-your-purpose)、[S02](https://www.agu.org/-/media/files/fall-meeting/preparing-presentation-guidelines.pdf)

- **任务目的：** 让不熟悉具体工作的同行理解研究问题、贡献为何可信以及适用范围。长篇邀请报告与短口头报告可使用不同深度。
- **必要信息：** 必要背景和具体缺口；核心贡献；足以理解贡献的机制或方法；最关键的证据和比较；结论、限制与意义。方法论文需要更多方法解释，不能把“少细节”理解为删掉核心算法或假设。
- **证据与反馈：** 选择能回答中心问题的结果，说明比较条件；复杂数据先解释读法。问答资料可保存补充验证和实现细节。
- **不适用情形：** 不适合作为完整实验日志、项目验收清单或逐图文献翻译。会议另有格式、录播或可访问性要求时，以本次官方要求为准。
- **评价维度：** 听众可理解性；中心贡献辨识度；证据支撑程度；结果与意义连接；时间内的信息取舍。具体时长由实际活动给定。

## project：项目汇报

**来源事实。** DARPA 的 Heilmeier 八问涵盖目标、现状限制、新方法、意义、风险、成本、时间及阶段性成功检查；该页面本次取得完整八问的官方索引内容，后续全文请求超时。[S04](https://www.darpa.mil/about/heilmeier-catechism) NIH RPPR 将目标下的完成情况、产品、下一期计划以及变化和问题分开记录，且年度与结题报告的信息要求不同。[S05](https://www.grants.nih.gov/grants-process/post-award-monitoring-and-reporting/reporting-requirements/research-performance-progress-report-rppr)

- **任务目的：** 对照双方约定的目标与成功判据说明项目状态，支持继续、调整、验收或资源配置。
- **必要信息：** 项目阶段及本次报告范围；约定目标与里程碑；完成工作和实际交付；对应证据、偏差与原因；重要风险、依赖及处理；下一阶段安排。
- **证据与决策：** 对重要目标给出“目标—当前状态—证据—差距”的可比较关系。需要对方决定时，说明选项、影响及所需输入；没有决策需求可明确说明当前仅供知情。
- **不适用情形：** Heilmeier 是项目构想与评估框架，不是所有已立项汇报都必须逐问作答的 PPT 模板。科研合作中的阶段讨论也不应自动变成合同验收。结题不强制填写“下一报告期”或预算续期内容。
- **评价维度：** 目标覆盖；证据可追溯；交付与工作活动区分；偏差解释；风险处理；决策可用性。合同与资助机构的本次要求优先。

## proposal：开题报告

**来源事实。** MIT EECS 强调研究价值、可行性和剩余工作的明确范围；AeroAstro 的指南区分书面开题与口头评议，认为听众已经阅读书面材料时，口头报告可以减少文献铺陈并聚焦拟议贡献及问答。[S06](https://mitcommlab.mit.edu/eecs/commkit/thesis-proposal/)、[S07](https://mitcommlab.mit.edu/aeroastro/commkit/phd-thesis-proposals/)

- **任务目的：** 使评议者能判断问题是否值得开展、方案是否有依据、研究范围与进度是否可行。
- **必要信息：** 科学问题和现有缺口；研究目标与拟议贡献；方法、假设及实施步骤；理论、文献或前期工作提供的可行性依据；验证方式；资源、关键风险和里程碑。
- **证据与反馈：** 明确区分已完成结果、预期结果和待检验假设。讨论成功与失败可能如何被识别；反馈聚焦范围、关键假设、验证路径及资源条件。替代路线按真实风险需要展开。
- **不适用情形：** 不能要求已证明全部贡献，也不能凭空生成前期结果。委员会未预读材料时需增加背景。学校页数与章节比例不迁移为 PPT 硬规则。
- **评价维度：** 问题价值与范围；对相关工作的理解；方法与问题匹配；验证可执行性；资源和时间可行性；不确定性处理。

## defense：学位论文答辩

**来源事实。** MIT EAPS 将答辩目的表述为展示达到一定质量的独立研究及清楚表达结果的能力。MIT BE 的答辩案例强调贡献和限制，并明确指出多项研究可以按独立章节组织，不必遵循线性历程。[S12](https://eaps.mit.edu/education/graduate-program/graduate-resources/#thesis-defense-graduation)、[S09](https://mitcommlab.mit.edu/be/2026/02/25/defense-season-wrapped-what-makes-a-thesis-defense-great/) 旧 MIT 写作指南提供背景、问题、方法、结果、结论的简要参考顺序。[S08](https://web.mit.edu/course/21/21.guide/th-defen.htm)

- **任务目的：** 让委员会能评判学位研究的完成情况、贡献及作者对工作的掌握；面向公众的部分同时需要可理解的背景。
- **必要信息：** 研究范围与动机；各研究部分及其关系；作者完成的贡献；关键方法、结果与验证；限制和结论。合作研究应使本人工作可辨识。
- **证据与质询：** 将主要贡献连到具体证据、比较条件和边界；为重要假设与潜在替代解释准备回答。以完成研究为依据，未来计划不代替已完成贡献。
- **不适用情形：** 多篇论文或不同项目构成的学位工作可以分组组织，应如实说明联系；不强制虚构“唯一统一问题”。答辩形式、时长和评审程序由学位机构决定。
- **评价维度：** 贡献及作者角色清晰度；证据充分性；方法理解；跨章节导航；限制诚实性；质询回应能力。仅凭 PPT 不能自动判断是否应授予学位。

## literature：文献研读

**来源事实。** UVA 建议围绕中心主张选择关键实验，允许不按原文图序逐图介绍，并将讨论是否聚焦论文作为主持者的责任。NYU 的研读框架同时检查研究设计、结果有效性、局限与应用情境。[S10](https://med.virginia.edu/research/pharmacology/current-students/degree-requirements/journal-club-tips)、[S11](https://hslguides.med.nyu.edu/EBM/journalclubs)

- **任务目的：** 解释原文的研究问题和证据链，并判断它为何可信、哪里有局限、哪些思想值得借鉴。
- **必要信息：** 可定位的论文身份与选文理由；必要背景；主张、机制或方法与假设；关键图表和条件；结论与局限；需要讨论的判断。
- **证据与反馈：** 关键图表绑定原文图号或页码，区分作者结论、报告者解读与额外推断。讨论可聚焦缺少的对照、竞争解释或向当前研究迁移所需条件。
- **不适用情形：** 不要求把所有论文强行填成临床 PICO、样本随机化或临床效应框架。理论、算法和数值论文应转换为对应的假设、证明、基准与验证条件。入门教学可增加概念解释；方法复现可增加实现细节。
- **评价维度：** 原文忠实性；机制理解；证据与结论匹配；批判性判断；迁移条件清楚；讨论价值。不能以期刊声望或作者身份替代证据判断。

## 对现有配置的定向建议

保留六个稳定 ID 及现有目的划分。最应修正的是 defense 的“论文的统一问题”：改为“论文研究范围、主要问题及各部分关系”，允许独立章节。proposal 的前期依据应允许缺省，以真实文献或理论可行性补足论证，并将计划与结果分开。project 应区分阶段汇报与结题；literature 应补上原文定位和作者结论/报告者判断的区分。group 的结构可以随诊断、设计讨论或进展分享变化。

现有 `generation_context()` 中的字号、条目数、图表数等属于产品默认设置，不能用本次用途来源把它们升级为普遍学术规范。本材料没有完成这些视觉默认设置的单独核验。
