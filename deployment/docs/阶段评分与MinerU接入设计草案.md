# 阶段评分、六种PPT用途与MinerU接入设计草案

日期：2026-11-02。状态：Q1–Q6及云端优先的更新均已得到用户答复；阶段评分、六用途规则与独立评审接口已发布到生产工作台。本文件保留最初设计的解释，实际结果以 `docs/阶段评分与知识库实际接入结果.md`、`reports/quality-release-files.json` 和解析回执为准。

## 这次要完善什么

用户要求知识库文件通过 MinerU 形成高精度 Markdown，允许有依据的更好方法；三种PPT视觉风格只是临时选择，六种用途承担真实任务差异；任何阶段的产出都需要可解释评分和反馈。节点约束应连接用途、来源、产物和检查，不能只给生成提示增加一句“严格检查”。

视觉风格和用途是独立选择。用途决定信息和交流目标，视觉规则来自当前用户模板或所选主题。增加新视觉风格不需要重写六种用途；一个用途可以匹配多种风格。已发表图文和教材经验按条件使用，实际会场/学校/合同要求另行绑定。

## MinerU形成可回查的文档包

每个被纳入知识库的文档保留原件、MinerU原始结果、阅读版Markdown、结构化内容/页段定位和图片资源，以及解析和复核记录。Markdown作为统一检索和阅读视图；对原生PPTX/DOCX的母版、对象、样式、字体和编辑能力，继续保存原件及其结构profile。将全部文件只剩一份Markdown会丢失严格模板检查所需的信息。

对PDF/扫描件优先试验适用版本的高质量档；原生Office/HTML使用该版本支持的原生解析路径。MinerU4的PDF高质量档是Standard/Advanced，原生文档使用Flash；这里的Flash是该格式的实际原生路径，不能把它混同为PDF高精度验收。不要照搬3.x的旧backend与CLI参数。官方说明见 [tiers](https://opendatalab.github.io/MinerU/usage/tiers/)。

本地三本教材共1042页。六页云端实测及单页定向复测已经完成：纯MinerU默认Markdown有跨页归属和图示漏词问题；物理页恢复与独立原页补充后的六页组合通过38项关键锚点核对。三书批次已按每片180页、并发1启动。详情见 `reports/mineru-pilot-quality-review.md` 和 `reports/mineru-fullbook-runbook.md`。高精度仍以当前原页与结果比较为依据。

对照样本覆盖旧字形提取问题、英文和混排、分段、术语、例文及指令式教材版面；补充公式、表格、双栏和扫描来源后才能支持相应能力。现有样本不覆盖的文档类型保持未验证。

解析验收检查：实际页范围与顺序；正文段落的完整性；词语、否定、数字、单位和符号；公式上下标与结构；表格单元格/表头/脚注；图、图注及相邻正文对应；图像引用是否可用。页眉页脚移除需与正文区分，不能误删正式内容。长文档拆分时保留源页偏移、分片身份、图片路径和结果位置；合并后的页码不能只代表分片本地页。

程序可检查页覆盖、资源引用、空结果和结构一致性；高风险与抽样页由原页对照审读。报告各类型的实际错误、检查样本与覆盖，避免从少量页推断全书字符准确率。对错误页定向重跑或用第二种方法复核；模型修复的内容保留依据及候选身份，不能把推测写成原文。

已有审读的旧Markdown保留为旧派生版本；新结果保留原件关联和独立状态。原生MD/文本与配置记录直接标明来源类型。首批范围已确认是三本教材和六用途资料，尚未逐页审读的结果保持unreviewed，不覆盖已审读的内容。

## 六种用途形成节点输入与输出合同

来源核查与六用途详细卡见 `docs/ppt-purpose-evidence.md` 和 `quality-knowledge/ppt-purpose-source-notes.json`。以下是结合来源的系统设计，不宣称为任一学校统一制度。

| 用途 | 主要交流目标 | 内容计划与评分应重点核对 |
|---|---|---|
| 组会讨论 | 让组内成员能诊断、提出解释或建议下一步 | 当前问题、必要条件、进展与异常、竞争解释、具体反馈问题；没有成熟结果也可得到好的组会评价 |
| 学术报告 | 让同行理解并记住可信的研究认识 | 读者背景、问题、方法为何成立、最有力证据、贡献和边界；在给定时长内取舍 |
| 项目汇报 | 支持状态判断、资源安排、调整或验收 | 当前目标/里程碑、实际交付、证据与差距、风险依赖、需决定的事项；研究活动与交付分开 |
| 开题报告 | 判断问题价值、方案依据和开展的可行性 | 问题与现状、拟议贡献、方法与验证、前期依据、风险和计划；拟完成工作与已完成结果分开 |
| 学位答辩 | 让委员会评价已完成研究与本人贡献 | 各部分联系或独立分组、方法与证据、作者贡献、对照与限制、可供质询的技术细节；不强造统一故事 |
| 文献研读 | 让听众理解并批判性讨论原文 | 原文身份与条件、方法机制、关键图证、贡献/局限、自己的解读及与项目关系；不把解读写成原文结论 |

每个PPT节点接收 purpose、audience、duration、source_versions、template_profile、applicable_rules。计划输出关键主张、证据定位、页面安排与待确认问题；制作输出原生文件与渲染；评审输出具体依据、用途维度、缺陷定位与修订建议。规则关注必要信息是否实现，默认不强制章节各占一页、固定页数或每页一个图。

## 所有阶段共用评审协议，各自使用合适标准

每个有意义的阶段产物都评审；不对每条日志、工具心跳或普通聊天评分。阶段任务范围与证据要求先明确，评分才可解释。研究阶段的“好”是是否服务当前用途，不能把尚未产生结果的开题与完成实验的结果稿共用成熟度标准。

| 产物/阶段 | 应评价的目标 | 需要单独核验的事实 |
|---|---|---|
| 材料解析与建库 | 保真、完整、可回查、可检索 | 原件版本、页段映射、引用资源与实际解析结果 |
| 想法与问题界定 | 问题清楚、研究对象与用途明确、未知暴露 | 区分事实、设想和作者选择；不以缺少最终结果扣分 |
| 文献与现状 | 来源支持、覆盖当前问题、条件和反证充分 | 实际阅读范围、引文支持与来源版本 |
| 概念/方案 | 机制、假设、可实施与可证伪性 | 已有证据、关键依赖与作者确认 |
| 程序/计算/证据 | 实现与目标一致、结果有效、可复现 | 实际运行、独立基准、数值/物理性质与配置 |
| 图表/可视化 | 信息准确、图证可读、对主张有用 | 原数据、单位、对象/样式、实际导出 |
| 手稿/翻译 | 命题与来源准确、论证与表达、目标规范 | 数字、术语、确定程度、参考文献、样式与渲染 |
| 幻灯片 | 用途目标、证据、讲述与呈现 | 模板/字体、可编辑对象、内容完整性、最终渲染 |
| 审查/交付 | 问题实质性、修改落实、回执真实 | 产物与检查同版本、所有权、保存回读和剩余限制 |

每次评审保留 task/stage、artifact identity+revision、rule/rubric version、实际输入、reviewer/tool version、检查覆盖、结果、缺陷定位与建议。自报检查与独立检查分别注明。原件、产物或规则变更后，相关评审标记过期，不能复用旧高分给新文件背书。

## 三部分结果共同解释质量

1. **硬性条件结果**：passed / failed / unknown / not_applicable，并附证据。必要条件unknown表示未完成检查，不等同失败或通过。
2. **分项评分**：依据当前用途评价质量。候选0–4锚点为：0未实现/无效，1存在严重缺口，2部分可用但有实质不足，3满足当前阶段使用目的，4有明确的额外质量收益。该0–4刻度与核心项至少3级已由作者确认；百分制仅作展示，权重留待真实样例校准。这些是产品约定，不来源于期刊或大学。
3. **覆盖与不确定性**：实际检查了哪些对象/来源/页段，哪些未查。未取得依据的分项保持未评，避免把缺失项归一化后得到虚高总分。

不得以审美高分抵消原文失真、错数值、缺来源或违反硬模板。总分用于同一任务与rubric下的比较；不同用途、不同成熟阶段与不同rubric版本之间不直接排名。评分是审读判断，不能视为客观正确率或科学结论已被证明。

修订应指向观察到的问题，改变产物后重新评审受影响部分，同时核对原有要求未被破坏。评分变化必须能够由实际变化和依据解释。评审没有新信息时不继续增加轮数或扩大任务。

## 与现有项目的关系

实际接入的HKUDS/Paper2Slides是内容规划与图像生成流程，尚未包含此通用评分模块。另一个paper2ppt项目的DeckIR/scorecard/修订回路可以作为工程参考，但项目身份、已有能力与研究建议需要分开。核查记录见 `docs/stage-scoring-existing-review.md`。

新增质量评审层应挂到现有持久任务、产物版本与回执上。Dify节点读取/执行规则和评审结果，Tutor解释并修订，Code/本机工具执行可计算检查。保存回执保持原有语义，质量结果另外表达。缺少评分、来源或检查证据时不能借保存成功宣告阶段质量已通过。

## 已确认政策

- Q1：每阶段给分项评分和依据，关键硬约束失败/缺必需证据时阻止自动流转，保留作者明确带偏差继续的决定。
- Q2：自动按具体缺陷修订并复评，最多两轮后交作者决定。
- Q3更新：没有现成自托管时复用现有MinerU云端配置；若比较证据表明自托管精度更高，可在集群配置。原件、页码和资源关联继续保留。

Q4确认0–4分项、核心维度至少3级和独立硬检查。Q5确认六页验证后按实测安排1042页三书及六用途资料。Q6确认评审提供独立接口、默认继承Tutor。用户原话保存在 `reports/quality-design-decisions.json`；无需重复确认。当前自动修订执行器已接PPT内容计划，最多两轮；其他阶段保存评分与具体问题，由相应执行器或作者处理，不能把通用预算误报为所有格式均已具备自动改写器。
