# Deep Partner 产品开发状态

目标是让计算科学研究围绕前人工作和作者确定的主线持续推进：文献、代码、计算、解释、写作与汇报连接在同一项目中。总览按研究主线、主任务和细节任务组织；研究行动由当前问题与证据决定，不按固定科研阶段排队。

## 已确认的协作与产品选择

作者选择研究总览为默认入口，对话贯穿其中。在已确定主线与资源范围内自主接续，关键科学选择或范围改变时提出具体问题。收到纠正后回查来源，修订受影响认识和任务，展示前后变化；作者意见不自动变成科学事实。验收同时覆盖氯硫与水化两条真实路径。子代理目前只读审计，主代理唯一负责共享文件、集成、部署和最终验收；后续并行开发须分工并使用独立worktree。

## 明确推荐的运行层迁移路线

采用Deep Agents/LangGraph作为研究决策循环的迁移目标，通过现有TurnEngine.execute(context)接入；保留账户、模型、会话、来源装配和StreamEvent外层。现有research_workbench与Slurm服务变成身份绑定工具，项目研究资产继续保存在业务层，LangGraph持久检查点负责执行接续。旧会话和未完成任务继续原引擎，新研究会话可逐步切换。作者在最新Linear讨论中明确希望配置Temporal，因此调整为正式引入并接管新simulate任务的外部生命周期；旧任务保留原调度器，Dify继续承担现有确定性检索和交付服务。具体接口、所有权、提交核对、部署与故障验收见[研究运行层迁移设计](研究运行层迁移设计.md)。

依据：assistant-ui官方ExternalStoreRuntime允许现有状态管理；Deep Agents官方SDK支持模型、工具、技能、backend和checkpointer。原生TurnLifecycle可注入turn_engine，executor消费StreamEvent。这是已完成代码审计的迁移方案，SDK尚未安装或通过项目级故障验证。整体切换前需要迁移范围确认及真实路径验收。

## 每批完成时的批判性复核

用作者当前语境向实现方提问，再对照Linear已有讨论、代码与实际路径作判断：

- “你这个改动，到底让研究工作更清楚了，还是又加了一个页面？”
- “你说验收通过，测的是能显示，还是用户真的能接着研究？”
- “有成熟工具为什么还自己写？换了工具具体解决什么问题？”
- “这个局部问题已经够用了吗，再追下去是否稀释主线？”
- “你完成的是回放、真实执行还是科学验证，是否说混了？”

本批结论：研究大纲和纠正已形成真实读写闭环，但不能据此宣称通用运行层已完成迁移；assistant-ui解决显示组件，不自动解决刷新、取消和附件数据链；已有Slurm结果回查不能冒充实时接续验收。每个有意义阶段复核一次，避免每个微小修改都增加仪式性审查。

文献基准页及研究侧栏的加载、选择、来源打开、发送、工具结果、作者等待、取消确认和刷新接续本批已交付。运行层设计已具体化，尚未安装或切换Deep Agents/Temporal，不能将设计交付称为迁移完成。

## 真实交互验收揭示的问题

两条真实研究验收副本的已保存纠正均已被后续paper写作上下文读取（research-correction-writing-context.json）。文献真实136条列表的排序、键盘详情、无结果清除、菜单和390/1100宽度均通过；截图另外发现旧样式覆写新标题与筛选栏，已移除继承。组件接入的三份React来源已统一为既有运行时19.2.3；71文件类型检查0错误，40项工作台和59项统一界面测试通过。

真实作者待答→刷新订阅原turn→答复继续已通过；继续发送下一句却被拒绝为已有活跃任务。根因在原生executor：终态已落库并发DONE，但标题生成仍占用coordinator的session lease。当前服务实际使用MemoryCoordinator，不是Redis；修复在DONE前核对持久终态、停止heartbeat并释放占用，保持旧turn的事件fencing身份；MemoryCoordinator显式release不再进入过期worker恢复扫描。普通异常路径同时改为先持久终态再发DONE。

11项定向检查复现旧实现问题并验证三种终态立即受理下一轮、迟到标题与旧清理不释放新lease、运行中拒绝提前DONE。三份实际生产源码已持久挂载发布，发布时无queued/running/waiting_input原生执行；服务健康。修复后完整浏览器路径已通过：真实作者提问、刷新订阅原turn、回复继续、立即下一轮、取消请求和执行端终态一致。

迁移审计还发现待实施的具体缺口：图谱HTTP分页上限及跨页关系遗漏；研究修订多文件写入的部分成功窗口；现有Slurm提交成功到回执落盘间的歧义；仿真桥尚无真实取消操作。这些进入运行层迁移批次，不包装成当前修复已覆盖。
