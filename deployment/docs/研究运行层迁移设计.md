# 研究运行层迁移设计

2026-11-05。依据实际代码审计、作者新增的 Temporal 选择和官方运行语义。当前是实施设计；Deep Agents 与 Temporal 尚未接管生产任务。

产品目的：研究 agent 沿作者确定的主线持续调查、调用工具、接受纠正并继续工作；外部计算能在断线、服务重启和回执丢失后接续同一次实验。研究步骤由问题与证据决定，调度器只管理已受理任务的执行。

## 职责和所有权

| 层 | 接管内容 | 保留实现 |
|---|---|---|
| Deep Agents / LangGraph | 研究决策循环、工具选择、同线程检查点、作者中断 | 原生身份、模型权限、来源装配、会话和事件持久化 |
| 工作台业务 API | 请求受理、项目权限、作者选择、研究资产版本、前端查询 | 项目文献、文件、图谱、大纲、任务与修订记录 |
| Temporal | 新 simulate 任务的准备、提交核对、等待、收集、核验、归档和取消 | 既有科学输入、SSH、Slurm、保存和独立核验代码 |
| 既有执行器 | 历史任务的执行和恢复 | 未完成任务保持原身份、原引擎和原目录 |
| Dify 服务 | 已实现的检索、网页与交付服务 | 确定性业务回执与授权检查 |

每项新实验只登记一个执行负责人。旧恢复扫描、GET 状态触发的恢复、工具桥启动扫描和维护线程都必须跳过 Temporal 所有的任务。把旧的长轮询函数包进一个 Activity 不满足这一条件。

## 受理与持久身份

保留现有 research-flow/runs 请求接口。服务器按项目配置选择引擎，在受理事务中登记请求和待启动记录。新增字段由服务器写入，模型不能指定授权或伪造已有回执。

```text
execution_backend = legacy | temporal
execution_version = simulation-v1
operation_id = simulate-<workbench_job_id>
workflow_id = simulation/<project_id>/<workbench_job_id>
request_revision, request_ref, authorization_ref
workflow_run_id = 最近观察到的 Temporal Run ID
phase = prepare | submit | submission_unknown | monitor | validate | archive
external = cluster, remote_root, slurm_job_id, slurm_state, observed_at
control = revision, pause_requested, cancel_requested, waiting_decision_id
projection_version = 已写回业务库的状态版本
```

缺少 execution_backend 的历史任务解释为 legacy。受理后不改变 backend；新实验尝试产生新业务任务。Temporal Run ID 会变化，不能用它构造 Slurm operation_id。启动响应丢失时查询固定 Workflow ID；不得直接创建另一个工作流。

## ExperimentWorkflow

```text
读取与校验冻结请求
→ 等待必要作者决定或已设停留点
→ prepare_files
→ submit_or_reconcile
→ [Workflow 定时等待 → poll] 重复至真实终态
→ collect_and_check
→ publish_result
```

文件、HTTP、SSH、数据库与 Slurm 操作放在短 Activity；等待使用 Workflow timer，不持续占用 SSH 连接或工具桥线程。暂时网络故障可以重试同一个操作；权限错误、非法输入和科学判据失败不能重试成新计算。历史只保存必要控制数据与文件引用，原始结果仍留在集群。

现有 cluster_simulation_runtime.run 在一次调用中准备、提交并每12秒轮询，工具桥同时自动恢复。新短操作应单独实现 v2，旧 run 保持历史任务兼容。工作台的 schedule/recover/execute 与工具桥的 schedule/work/两处恢复扫描同时校验所有权。

## 提交成功、回执未落盘的窗口

现有 submit_once 有远端锁和原子回执，但 sbatch 成功后、回执落盘前退出仍可能重复提交。新提交包装器在远端 operation 目录先写 submission-intent，记录请求版本、脚本与提交时间范围；sbatch 携带稳定 operation 标记，并使用唯一运行目录。

重入先读回执；只有意图没有回执时，按标记、用户、目录和时间范围核对 squeue/sacct。唯一匹配则补回执；多项或证据不足保持 submission_unknown，不自动重提。暂时查不到不能等价为从未提交。这提供原身份核对和歧义停留，不宣称跨数据库、SSH、Slurm 的绝对恰好一次。

## 等待、暂停与取消

- 作者等待绑定 decision_id、expected_revision 和服务器授权记录。答复使用可校验的 Update；过期答复不能恢复另一问题。
- 暂停阻止后续阶段；已经提交的作业仍可运行，界面同时显示编排暂停与实际集群状态。
- 取消先记录意图；提交前可结束，提交不明时先核对。已提交时校验作业归属后 scancel，再查询终态。取消请求已受理不等于集群已停止。
- 常规界面不把 Temporal terminate 当作取消入口，因为强制终止不能替代清理和核对。

现有仿真桥没有真实 cancel/scancel 操作，必须实现后才开放这项产品能力。

## Agent 生命周期和事件接口

接入位置为 TurnEngine.execute(context)，继续由原生 TurnLifecycle 分配事件序号并保存。新研究会话保存 engine、engine_version、configuration_version 和 LangGraph thread/checkpoint 绑定；每轮恢复原线程，不重新创建孤立研究状态。浏览器重连仅订阅已有执行。

| 内部事件 | 现有公开事件／业务状态 |
|---|---|
| 受理 | session，保留原生 session_id / turn_id |
| 公开回答增量 | content |
| 调查和工具开始／更新 | stage_start / progress，稳定调用 ID |
| 工具调用／返回 | tool_call / tool_result，关联同一工具调用 |
| 来源读取 | sources，真实版本、页码／行号与读取范围 |
| 作者中断 | wait_for_input，持久 interrupt ID |
| 外部计算等待 | waiting_external 进展和工作台 job 引用 |
| 成功／失败／确认取消 | result / error 后由原生事件层写 done |

Temporal 任务完成到研究 agent 恢复需要持久收件记录和去重。授权在业务工具边界重新核验，不由模型填写“已批准”。单个运行只允许一个 worker 持有执行权，旧 worker 失去租约后不得继续写入。

## 先修复的资产一致性缺口

research_updates.apply_update 当前依次写图谱、关系、大纲、回执、历史；进程内 RLock 不能覆盖多个服务。后一步失败可能留下部分修订。这与成功路径的来源核验是两个不同问题。

实施时增加稳定 operation_id 和可恢复修订提交日志，在第一次可见写入前保存修改集、基准版本、目标版本与待写内容。用同项目跨进程锁协调全部读写入口；各文件原子替换并登记进度，最后才标 applied。同 ID 同内容重试恢复原提交；同 ID 不同内容拒绝。读取或其他写入遇到未完成提交，先恢复或明确返回等待恢复，不能把混合版本交给下一轮写作。

这是一项可恢复多文件提交，不是文件系统跨文件事务。应注入各写入点失败，确认不会提前报告完整成功。

图谱另有已确认缺口：HTTP limit 被截到200，工具请求2000不会取得全部；现有每页 edges 只包含两端都在本页的关系。补充独立关系分页或 boundary_edges，保留旧画布单页语义。所有页绑定同一快照版本，该版本还应覆盖动态加入的文献索引；页间版本改变时有界重取，持续变化则明确报告，不能返回伪完整结果。

## 部署与验收批次

1. 完成研究修订的恢复日志、跨进程一致性和完整图谱分页。覆盖逐写入点失败、响应丢失、并发纠正和201节点跨页关系。
2. 配置独立 Temporal 服务、持久数据库、开发／验收／生产 namespace 与能力分开的 task queue。服务仅在现有受控网络访问，凭据从部署环境注入，仓库保留模板。备份、恢复和升级演练包含服务数据库与工作台请求记录；start-dev 仅用于开发。
3. 接入新 simulate 请求和唯一调度权。通过真实业务 API 与 Temporal 服务，使用可控执行器演练重复受理、启动响应丢失、worker／工具桥重启、旧扫描遇到新任务。
4. 接入真实 SSH/Slurm v2 短操作。演练提交前、提交成功回执前、回执后、取消后的断线及收集重试；核对原作业，不重复提交。用已授权真实工况进行接续验收，不把旧回执回放称为实时恢复。
5. 接入 Deep Agents 完整事件映射，走氯硫与水化两条真实研究路径。覆盖作者纠正、原文读取、写作上下文、外部等待及成功工具后 worker 退出。验证通过后才切换新会话默认引擎。

关闭新引擎开关只影响后续受理；不把故障中的同一任务交给旧引擎自动重跑。回滚需要先核对原检查点、原 operation 和外部状态。
