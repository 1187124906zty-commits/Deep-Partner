# Deep Partner 工具调用与自动恢复

2026-11-05。当前边界覆盖已接入 Deep Partner 的 Scholar、ScanSci、DeepCode、Paper2Slides、集群 PDF 解析、集群仿真，以及项目文件和运行回执的保存。正常调用以实际工具响应及所需产物的保存回读为准；提交成功另行记录，不等同任务完成。

可控的运行故障由程序负责恢复。独立守护每约20秒检查本机工具服务，实际核对远端 HTTP 入口，恢复已配置的桥接、SSH反向连接及已配对下载进程。工具桥与守护互相恢复，用户登录时启动。守护不逐次运行模型或求解器做健康检查。Windows拒绝了计划任务登记，因此当前使用用户登录启动与两个独立进程互相恢复；两者同时被终止时，下次工具调用或用户登录会恢复入口。

| 环节 | 自动恢复行为 |
|---|---|
| Scholar | 恢复桥接和反向连接，重试原工具及原分页参数；保留诊断，不因断连切换检索来源 |
| ScanSci | 重启空闲或已退出的配对进程；临时传输失败保留原下载ID、本机文件和集群副本，按冷却时间接续原阶段 |
| DeepCode | 使用真实 MCP 与原生生命周期；记录原生会话、turn或workflow ID，客户端断开后读取同一执行；已授予项目的修改/测试权限映射到新执行目录 |
| 集群PDF、仿真 | 保留原Slurm ID并接续查询；提交在远端加锁并保存回执，SSH响应丢失后取回原作业号 |
| Paper2Slides | 规划和导出分别绑定确定的子任务ID；提交响应丢失后对账同一子任务，保留既有评审及作者选择 |
| 产物保存 | 每份源码保存回执与内容版本，部分保存后接续其余文件；排除运行时配置和锁文件，保留用户修改冲突 |

短期故障采用有限主动重试。8次后进入 `waiting_service`，每5分钟做一次便宜的健康探测；服务恢复后自动接续原run，无需重新发送需求或输入resume。外部任务正常排队、长时间求解属于 `ToolPending`，不消耗故障预算。

限流进入冷却后重试原请求，遵从可用的Retry-After信息。验证码、登录、新权限、作者的方案/结构决定显示为明确等待；用户完成后接续已有任务。输入不合法、用户取消、数值检查失败等保留真实状态。无法证明旧任务是否仍在执行时保留待核对状态，避免重复副作用。

已中断且没有执行回执的旧版Paper2Slides子任务仍需核对；新版确定ID解决的是交接和重复调用。自动恢复负责工具执行条件与进度，模型、边界条件、研究判断及作者决定按具体任务处理。

实际验收包括56项服务器候选测试、5项本机恢复合同测试、1项产物过滤测试，以及五项真实故障注入。Scholar隧道、Scholar桥接、ScanSci进程、独立守护和工具桥分别被停止后自行恢复，实测约18—41秒，测试没有调用手动修复。正式入口另完成全新会话原生代码执行与两项独立测试、Scholar检索、Poisson制造解；Slurm提交回执重复读取返回相同作业 `25419604`。

还实际验证了整条恢复链：停止Scholar桥接后，经正式项目接口发起检索，运行 `35abc98a58d74817a19c732842cc1679` 记录到 `bridge_transport_error`，自动等待、重连并完成同一run，返回1条真实题录。测试未调用手动恢复或resume，未切换检索来源。

详细回执：

- `reports/partner-tool-autorecovery-live.json`：五项真实进程/连接故障。
- `reports/partner-recovery-release-live.json`：正式入口的新会话执行、检索和集群结果。
- `reports/partner-scholar-same-run-recovery.json`：断连后原项目任务自动完成。
- `reports/partner-recovery-deployment.json`：正式部署及候选测试数。
- `reports/partner-recovery-cooldown-deployed.json`：限流冷却修订及最终56项测试。

新工作流带 `automatic-recovery-1` 标识，适用本恢复流程。发布保留原工作进程完成已有任务，避免接管未持有新版执行锁的旧任务；旧任务的明确项目范围单独保留。
