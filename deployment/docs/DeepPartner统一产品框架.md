# DeepPartner 统一研究产品框架

2026-11-02。依据本轮明确需求和三个源代码审计确定的实施框架；这是正式产品改造，不另建一次性演示。

## 产品过程与取舍

唯一业务单位是研究项目；项目绑定原生 workspace。对话提出问题、组织任务与接收反馈，成果区查看、编辑和批注产物，两者共用原生 session/turn。批注发送到当前项目会话；没有会话时由原生运行时创建。保留工作台文献、文件、论文、PPT、版本和审查能力。检索、评分、委派和交付是可折叠活动，必要的人工问题和失败仍明确出现。

研究界面不展示中小学课程、练习和掌握路径的产品入口。通用研究阅读、提问、可视化、附件、知识检索、技能和MCP仍由运行时按任务使用。普通设置保留账户、外观、输出语言、项目及本机工具；模型编排、知识库模型和Agent配置留在现有管理入口，不成为日常必填。

产品名不意味着强制新建Partner persona，也不意味着替换Tutor的持久运行时。继续使用原生ChatWorkspace、ChatRuntimeProvider、v2协议、消息与trace存储。工作台成果、批注、评分与Dify运行保留本身身份，以结构化session/turn关联串联，不复制第二套聊天存储。

## 视觉与布局

设计来源是DeepTutor真实Web源码；采用Claude风格light奶油与dark暖黑主题。主要颜色直接沿用背景#fdfcf9、文字#1c1816、主色#b0501e、次表面#f5f2ea、边线#e6decc和弱文字#6d645a。Geist用于界面，Lora用于现有衬线表达，中文沿用原CJK回退。字体随前端作为本地静态资产发布，修复服务器磁盘路径404。MotionProvider、AssistantActivity、TracePresentation与原聊天组件直接复用。

布局：单一侧栏容纳项目与会话；中央是当前项目的对话或成果区，可在宽屏同时查看。成果区只保留业务标签、文件工具和内容，没有第二套品牌侧栏。窄屏切换对话与成果；所有主题来自同一token源。先保证真实组件一致，再调整工作台控件的间距、边框、焦点与空状态。不会靠iframe把两个完整应用拼在一起。

## 交付与更新边界

同一个Vite React入口构建网站与桌面静态前端，直接消费DeepTutor的共享组件源，有限适配Next路由/lazy/image宿主接口。网站通过同源API；桌面使用Tauri/WebView2和既有Rust本机服务，安装包内置同一前端。Windows原生构建在本机完成，前端批量构建沿用集群Slurm环境。

本机Rust持有远端认证cookie；本地受保护HTTP/WS代理把共享UI接到同一会话，避免WebView与Rust分别维护身份。只接受本机绑定、精确Origin与本机session；远端token不进入前端存储或日志。原有文件、浏览器和桌面工具复用。桌面与dp共用CLI任务实现和事件日志。

Dify发布、Tutor技能部署和MCP注册各有真实入口。服务端版本化manifest聚合协议版本、技能规则、已接入工作流与能力；客户端启动、恢复联网和定期刷新。兼容改动自动用于新任务，正在执行的任务保留实际运行/输入身份。破坏协议或新增本机能力必须手动升级前端/安装包，manifest明确报告。自动同步是发现并使用服务端发布能力，不是从Dify静默下载执行任意桌面代码。

Codex/Claude Code使用本机安装与各自登录，和服务器CLI分开检测。独立dp提供doctor、任务启动/状态/事件/取消；GUI调用同一核心。真实执行记录cwd、engine、job_id、退出状态和事件。桌面任务入口清楚显示本机能力；缺失工具给出真实状态。尚未配对的普通用户不继承运营者SSH。现有个人SSH桥只作兼容功能，不包装成公网多设备配对。

## 设计压力检查与决定

1. “所有东西在Dify改”不成立：Dify只能发布它管理且已接入的流程。决定：保留各管理入口，统一发现与调用契约。
2. 在线加载网站不能满足前端手动升级。决定：桌面内置前端；网络只提供数据、事件与兼容能力声明。
3. 只换配色不能消除两张皮。决定：复用原聊天与provider，移除工作台重复外壳，并将批注回送同一会话。
4. 藏起过程不能藏起需要用户处理的等待和失败。决定：默认折叠工具细节，保留执行状态、人工问题、失败和可展开证据。
5. 本机CLI调用不等于服务端CLI目录。决定：独立本机检测、任务生命周期和取消，界面直接连接真实本机任务。

## 验证要求与当前状态

共享前端真实编译、原生会话流式输出/恢复、成果读取与同会话批注、字体、实际WebView2启动、dp真实CLI事件、取消与manifest兼容处理已经完成有限验收。实现与当前边界见[DeepPartner0.4实际交付](DeepPartner0.4实际交付.md)。测试验证正式实现，不以mock界面作为交付；安装包已经生成，安装目录没有被静默替换。原生保存对话框的完整人工路径未在本轮自动化验收。
