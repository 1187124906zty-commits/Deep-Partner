# 真实下载链路与登录恢复

2026-11-02 已修复管理员本机下载设备离线导致文献长期排队的问题。原任务保留原 ID，已完成本机 ScanSci 取全文、PDF 身份核对、集群上传及副本验收，并由集群直接交付到所属项目文献库。

根因是下载 worker 已经退出，而旧桌面登录只恢复模型、电脑工具桥和集群连接，没有恢复已配对的下载设备。配对凭据存在不代表设备在线，任务卡能显示流程也不代表流程已经实际执行。

新版 Windows 主程序在账户登录后，按本机已配置的账户身份恢复对应下载 worker。它复用现有 ScanSci Python 环境、设备凭据和专用机构会话，写入真实运行心跳；重复连接复用同一进程，OS 单实例锁避免同一设备配置被多个 worker 同时使用。Windows 虚拟环境启动器与实际 Python 进程的 PID 不同，状态接口在收到心跳后统一返回实际 worker 的 PID。

当前机器的下载设备已经恢复在线。用户正在使用的窗口保持打开，后续启动更新后的主程序时将采用上述登录恢复逻辑。本轮已用更新后的实际打包二进制启动隔离的 HTTP 宿主，登录真实账户验证自动启动；没有替换现有电脑工具桥，也没有强制关闭正在使用的窗口。
